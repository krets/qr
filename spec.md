:# Project Specification: QR Code Generator (qr.krets.com)

## 1. Overview

A modern, web-based application hosted at `qr.krets.com` that allows users to generate custom-styled QR codes from various data sources (WiFi, URL, vCard, Raw Text).

The application features a real-time canvas preview, deep customization options, and adheres to system-level light/dark mode preferences.

## 2. Design & UX Requirements

### 2.1 Visual Style

* **Layout:** Responsive "Split View".
* **Desktop:** Left Sidebar (Controls) | Right Main Area (Preview).
* **Mobile:** Stacked (Preview on top, Controls below).


* **Theme:**
* **System Sync:** Must utilize `@media (prefers-color-scheme: dark)` to automatically switch themes based on the user's OS settings.
* **Light Mode:** White/Light Gray background, dark text, high contrast borders.
* **Dark Mode:** Dark Slate/Black background, light text, muted borders to reduce eye strain.


* **Aesthetics:** Clean, "Flat UI" or "Material" inspired. Rounded corners on input fields and buttons.

### 2.2 Preview Area

* **Canvas:** Centered, prominent display of the generated QR code.
* **Real-time:** The canvas must update immediately (debounced ~300ms) as the user types or changes settings.

## 3. User Interface: Input Controls

### 3.1 Data Tabs

The input area is divided into 4 tabs. Switching tabs updates the "Raw Data" context.

**Tab 1: WiFi**

* **Fields:**
* Network Name (SSID) `[Text Input]`
* Password `[Text Input]`
* Encryption `[Select]`: `WPA/WPA2` (Default), `WEP`, `None`.
* Hidden Network `[Checkbox]`: "Yes/No"


* **Logic:** concatenates fields into valid WIFI string.

**Tab 2: URL**

* **Fields:**
* Website URL `[Text Input]`
* *Validation:* Auto-prepend `https://` if missing.



**Tab 3: vCard (Contact)**

* **Fields:** (Only non-empty fields are included in output)
* First Name `[Text Input]`
* Last Name `[Text Input]`
* Organization `[Text Input]`
* Title/Role `[Text Input]`
* **Birthday** `[Date Input]` (HTML5 Date Picker)
* Phone (Mobile) `[Text Input]`
* Phone (Work) `[Text Input]`
* Email `[Text Input]`
* Website `[Text Input]`
* Address (Street, City, State, Zip) `[Text Inputs]`



**Tab 4: RAW**

* **Fields:** Data Content `[Text Area]`
* **Behavior:**
* Displays the underlying string generated by Tabs 1-3.
* Editable: Users can manually override the string here.



### 3.2 Styling Sidebar

**Global Settings**

* **Error Correction (Redundancy):**
* `[Select]`: Low (7%), Medium (15%), Quartile (25%), High (30%).
* *Help Text:* Display context-sensitive tips (e.g., "High: Recommended for print").



**Appearance**

* **Colors:**
* Foreground (Modules) `[Color Picker]`
* Background `[Color Picker]` (Default: White)


* **Shapes:**
* *Module Shape:* Square, Dots (Circle), Rounded.
* *Finder Pattern:* Square, Circle, Rounded-Square.



**Labels (Top & Bottom)**

* **Top Label / Bottom Label:**
* Text `[Text Input]`
* Alignment `[Radio/Icons]`: Left, Center, Right.
* Font `[Select]`: Sans-Serif, Serif, Monospace.
* Color `[Color Picker]`

## 4. Functional Logic

### 4.1 Data Formatting Schemas

**WiFi:**
`WIFI:S:<SSID>;T:<WEP|WPA|nopass>;P:<PASSWORD>;H:<true|false>;;`
*(Escape colons, semicolons, and backslashes with `\`)*

**vCard (v3.0):**

```text
BEGIN:VCARD
VERSION:3.0
N:Last;First;;;
FN:First Last
BDAY:1990-01-01
ORG:Company
TITLE:Job Title
TEL;TYPE=WORK,VOICE:(123) 456-7890
EMAIL:email@example.com
END:VCARD

```

### 4.2 Canvas Rendering Pipeline

1. **Calculate Matrix:** Generate boolean grid based on Data + Error Correction.
2. **Draw Background:** Fill rect.
3. **Draw Modules:** Iterate grid. Apply "Shape" logic (e.g., `ctx.arc` for dots, `ctx.rect` for squares).
4. **Draw Finders:** Detect 7x7 corner zones; apply specific Finder Shape logic.
5. **Draw Labels:** Increase canvas height; `ctx.fillText` at calculated coordinates.

### 4.3 File Export & Naming

* **Action:** "Download PNG" button.
* **Filename Logic:**
* Generate a short hash (e.g., MD5 or simple JS hash code) based on the **Raw Data String**.
* Format: `qr_[hash].png` (e.g., `qr_a1b2c3d4.png`).
* *Purpose:* Ensures unique filenames for different content, preventing accidental overwrites in the user's download folder.

## 5. Technical Constraints & Deployment

* **Hosting:** The application will be served from the root of the git repository at `qr.krets.com`.
* **Tech Stack:**
* HTML5
* CSS3 (CSS Variables for theming)
* Vanilla JavaScript (ES6+)


* **Dependencies:** Minimal. One lightweight library for QR Matrix calculation (e.g., `qrcode-generator`) is permitted. No heavy frameworks (no React/Angular/Vue) unless necessary for state management, but Vanilla is preferred for this scope.
